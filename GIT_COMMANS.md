1. Настройка и конфигурация
git config --global user.name "Ваше Имя"
Устанавливает ваше имя для всех репозиториев на этом компьютере.

git config --global user.email "your.email@example.com"
Устанавливает вашу почту для всех репозиториев.

git config --list
Показывает все текущие настройки.

2. Создание репозитория и клонирование
git init
Создает новый локальный репозиторий в текущей папке.

git clone <url-репозитория>
Клонирует (скачивает) удаленный репозиторий с указанного URL на ваш компьютер.

3. Основной рабочий процесс (снимок состояния)
git status
Показывает состояние рабочей директории и индекса: какие файлы изменены, но не добавлены в индекс, какие ожидают коммита.

git add <имя_файла>
Добавляет конкретный файл в индекс (staging area) для последующего коммита.

git add . или git add --all
Добавляет ВСЕ измененные и новые файлы в индекс.

git reset <имя_файла>
Убирает файл из индекса, но сохраняет его изменения.

git commit -m "Сообщение коммита"
Фиксирует изменения, находящиеся в индексе, и создает новый коммит с описательным сообщением.

git commit -am "Сообщение коммита"
Комбинация git add . и git commit -m для уже отслеживаемых файлов (для новых файлов не сработает, нужно сначала add).

4. Просмотр истории и изменений
git log
Показывает историю коммитов в текущей ветке.

git log --oneline — компактный вывод.

git log --graph — показывает ветвление.

git diff
Показывает разницу между рабочим каталогом и индексом (незакоммиченные изменения).

git diff --staged
Показывает разницу между индексом и последним коммитом.

5. Работа с ветками (очень важно!)
git branch
Показывает список всех локальных веток (текущая помечена звездочкой *).

git branch <имя_новой_ветки>
Создает новую ветку.

git checkout <имя_ветки>
Переключается на указанную ветку.

git switch <имя_ветки>
Новая, более интуитивная команда для переключения между ветками (похожа на checkout).

git checkout -b <имя_новой_ветки> или git switch -c <имя_новой_ветки>
Создает новую ветку и сразу переключается на нее.

git merge <имя_ветки>
Вливает изменения из указанной ветки в текущую.

git branch -d <имя_ветки>
Удаляет указанную ветку (если она уже была влита).

6. Синхронизация с удаленным репозиторием (GitHub, GitLab и т.д.)
git remote -v
Показывает список подключенных удаленных репозиториев.

git fetch
Скачивает изменения из удаленного репозитория, но не применяет их к вашим файлам.

git pull
Выполняет git fetch + git merge (скачивает изменения и вливает их в вашу текущую ветку). Эквивалент: git pull origin main.

git push
Отправляет ваши локальные коммиты в удаленный репозиторий. Эквивалент: git push origin main.

git push -u origin <имя_ветки>
При первом пуше новой ветки нужно установить связь с удаленным репозиторием. Флаг -u (или --set-upstream) делает это.

7. Отмена изменений и откат
git restore <имя_файла>
Отменяет изменения в файле (еще не добавленные в индекс), возвращая его к состоянию последнего коммита. (Новая команда).

git restore --staged <имя_файла>
Убирает файл из индекса (аналог git reset), но оставляет изменения в файле. (Новая команда).

git reset --hard <хэш_коммита>
Опасная команда! Откатывает и индекс, и рабочую директорию к состоянию указанного коммита. Все незакоммиченные изменения будут безвозвратно удалены.

git revert <хэш_коммита>
Создает новый коммит, который отменяет изменения указанного коммита. Безопасный способ отменить изменения в общей истории.
